# Design notes

The full argument, including the parts that cut against it.

## The problem on each side

| | Unsolved problem |
|---|---|
| **LLM Wiki** | superlinear query cost, no computable structure, contradictions found by brute force, silent drift |
| **Knowledge graphs** | extraction recall 0.38–0.55, over-merge, destroys nuance, unreadable by humans |

The lazy answer is "maintain both". It is a bad answer: it doubles the maintenance and the
two artefacts diverge. That is precisely the burden Karpathy identifies as what kills wikis.

## The move: extraction → declaration

Graph literature assumes the corpus is text you must extract from. In a second brain **you
control the writing step**, so you never extract — you declare, at the one moment when
context is maximal.

This is not a small optimisation. It removes the entire class of problems that graph
pipelines spend their engineering on: entity resolution becomes nearly unnecessary (the
wikilink *is* the canonical identifier), over-merge cannot happen (the author knows which
page they meant), and recall goes from measured-0.4 to structurally-1.0.

## One source, three projections

```
wiki/**/*.md          ← the only source of truth (prose + frontmatter)
   ├─ L0  edges.json  ← derived by script. Topology only
   ├─ L1  frontmatter ← ~60 tok/page
   └─ L2  bodies      ← ~1000 tok/page
```

Traversal is cheap because it is local and never passes through a model. The expensive read
is paid only at the leaves. This imports the graph's flat cost curve **without giving up
prose**.

## Contradictions: O(n²) → O(1)

Karpathy's lint asks the model to read everything and look for clashes. That is pairwise
comparison, and it does not scale: at 300 nodes nobody runs it any more, so contradictions
accumulate exactly when the vault is large enough for them to matter.

Declared at write time, it is a query. And the best-placed observer is the session doing the
writing, which has just read both the new source and the affected pages.

This is the single strongest argument for the whole design.

## Anchors

Borrowed from the *other* sense of "graph engineering" — the feedback-loop topology
literature, which at first looks irrelevant here and isn't.

Every page in a mature second brain was written by an LLM reading pages written by an LLM.
Over months that is many generations of chained compression. Errors do not get corrected in
transit; they get consolidated, and each rewrite makes them sound more confident because the
prose improves even when the fact does not.

> A graph that consumes only reports generated by other loops inside the same graph can be
> perfectly self-consistent while drifting arbitrarily far from reality.

The wiki version: **a vault without anchors is a well-organised echo chamber.**

The uncomfortable part is that a vault that has drifted and a vault that has compounded well
are indistinguishable from the inside. Both produce coherent, well-cross-referenced,
confidently-cited answers. Internal coherence is not evidence of correctness.

Anchors: `.raw/` immutable; provenance that must terminate in a raw document rather than in
another wiki page; `derivation_depth` as a measurable distance from ground truth; a frozen
gold set the system cannot rewrite.

## Explicit frontier

Gaps as first-class nodes. When a second brain suggests well, it is usually because the model
inferred the *shape* of your knowledge from the index — where it is dense, where it is empty.
That is indirect and fragile, and it degrades precisely as the index grows.

Declared gaps make it direct. Same move as declared edges, applied to absence instead of
relation.

## What this does not solve

1. **Author bias.** Declared edges are the ones the writing session noticed. A neutral reader
   might find connections the author missed. Recall goes to ≈1.0 for *intended* edges;
   serendipitous ones are lost. Partial mitigation: `wq.py undeclared` compares prose links
   against declared edges and proposes the difference, free.
2. **Frontmatter inflation.** Declare everything and the frontmatter stops being cheap, which
   kills L1. Ceiling: 5–7 edges per page.
3. **Writing discipline.** A lazy session that declares nothing creates a node invisible to
   the graph. The lint flags `relations: []`.
4. **Vocabulary rigidity.** A closed set that does not fit your domain produces forced edges.
   It should co-evolve — but deliberately, in versioned changes.
5. **Source quality.** Nothing here substitutes for curating good sources.

## Three falsifiable predictions

This is a design hypothesis, not a result.

1. **Cost.** Mean query cost should stop growing with node count. If it grows at the old
   rate, L0/L1 is not doing its job.
2. **Contradictions.** Edges declared at write time should outnumber what a full lint pass
   finds afterwards. If the lint finds many more, declaration is not working.
3. **Quality.** On a fixed gold set, answers via L0→L1→L2 should match or beat
   index→pages, with fewer tokens. **Matching with fewer tokens is already a win.** If it is
   worse, prose matters more than this design assumes — and that would be the finding that
   sinks it.

Prediction 3 is the one to run first, and `bin/snapshot.sh` exists to make it possible: same
gold set, same model, same settings, two states of the vault. Without holding the operator
and the model constant, you are measuring yourself, not the system.

## Lineage

- **Karpathy, LLM Wiki** — the pattern: prose that compounds, maintained by the model,
  schema co-evolved with the user. The ceiling he names — "~100 sources" — is a token
  ceiling, and it is what G² removes.
- **claude-obsidian** — the reference implementation. Its hot cache is a genuinely good idea
  and is kept here. Its single conversational session that mixes ingest and query is the one
  design choice G² departs from, because `effort` is part of the cache key.
- **Anthropic's knowledge graph cookbook** — the pipeline, and the honest evaluation that
  gave us the 0.38–0.55 number this whole design is a reaction to.
